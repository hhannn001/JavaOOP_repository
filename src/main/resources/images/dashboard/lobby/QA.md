# 로비 검증

- 실제 Swing 화면을 1280 × 830 창에서 열어 로비 합성, 메뉴 이미지, 리더보드 배치를 확인했다.
- 별도 임시 SQLite DB의 12명 기록으로 상위 9명과 개인 12위의 분리 표시를 확인했다. 검증 기록은 앱 DB에 추가하지 않았다.
- `DashboardRecordsTest`: 방별 분리, 동률(1·1·3), 상위 9명 제한, 9명 밖 개인 순위, 0초 기록, 미클리어, DB 장애 구분.
- `SceneObjectButtonTest`: 실제 PNG 알파, 3 × 2 프레임 규격, 중복 클릭, 마지막 프레임 뒤 콜백, 제거 시 콜백 취소.
- 기존 화면 전환·로그인·게임·기록 저장 통합 테스트도 실행한다.

## 구현 범위

커튼 천·캘린더 종이는 6장 이미지 포즈를 재생한다. 고정 사물 영역은 첫 프레임의 픽셀을 그대로 사용한다. 사물 형상이나 움직임을 도형·왜곡으로 생성하지 않는다. 고정 로비 메뉴 및 버튼 문구는 각각 PNG다. 이름·시간·순위·조회 상태처럼 실행 중 바뀌는 정보는 한글 글꼴로 표시한다.

풀이한 문제는 정적 책장으로 표시하고 클릭 시 미구현 안내창만 연다. DB 기록 조회는 하지 않는다.

최종 검증 명령: `./mvnw verify`

편집기의 동시 클래스 생성과 분리한 임시 소스 스냅샷에서 53개 테스트 통과(실패 0, 오류 0, 생략 0).
실행: `java -cp 'target/classes:target/dependency/*' coderoom.app.Main`

수정 회귀 검사: 책장/캘린더의 움직이는 영역 밖에서 프레임 간 변경 픽셀 0. 리더보드/캘린더 콜백 중 및 복귀 후 강조 해제, 실제 포인터 이동 후 재활성화 확인.

추가 회귀 검사: 책장 즉시 콜백, 단일 프레임의 정상 크기, 커튼 호버 제거, 창문 잎사귀 투명도·유리 영역 제한·낙엽 시작·종료 및 최소 10초 휴지. 실제 1280 × 830 Swing 화면에서 창문 합성과 사물 배치를 확인했다. 커튼/캘린더는 60ms × 6프레임(360ms), 창문은 40ms 갱신, 낙엽 사이 10~18초 휴지.
