# QA: CODE ROOM 검증 계획

상태: **계획 수립, 실제 Java 앱 QA 미실행**. 현재 운영 코드는 설계 초안이다. 웹 프로토타입의 `prototype/QA.md` 결과를 Java 완료 증거로 사용하지 않는다.

## 진행 순서와 기준

1. 각 담당자는 [Test 가이드](Test_드라이버_가이드.md)의 대역 드라이버를 실행하고 실제 코드 연결 테스트를 추가한다.
2. G가 임시 SQLite 초기화, B/C가 계정·맵 seed, E가 퍼즐 2개와 정답을 확인한다. 시연 계정 3개와 플레이 가능 맵 1개/준비 중 2개를 사용한다.
3. 각 파트 정상·실패·경계 QA 후 A가 전체 흐름을 연결한다. A↔E, B↔G, C↔D 교차 확인, F는 E와 입력 계약/A와 화면 연동을 확인한다.
4. 테스트마다 새 세션/임시 DB를 사용한다. 기록 유지 시나리오만 같은 DB로 재실행한다. OS·JDK·화면 크기·커밋을 남긴다.
5. P0/P1 결함이 없고 아래 필수 항목이 모두 통과하면 시연 준비 완료로 판정한다. 미실행·차단을 통과로 표시하지 않는다.

P0: 실행 불가·전체 흐름 중단·데이터 손실. P1: 핵심 규칙/기록/입력 실패. P2: 우회 가능한 표시·사용성 문제.

## PR별 완료 조건

- `./mvnw clean verify` 통과. 스텁 테스트 외에 수정한 실제 기능의 성공·실패 검증 증거 첨부.
- 화면 생성·변경은 EDT, DB/비밀번호 검증은 작업 스레드. 화면 종료 시 타이머와 지연 작업 처리 확인.
- app→pages→widgets→features→entities→shared 의존 방향 및 슬라이스 경계 확인.
- 남은 QA는 담당·기한·차단 이유 명시. 스크린샷에는 계정 비밀값을 포함하지 않는다.
