# Java 소스 구조 및 작성 원칙

현재 SQLite 로그인·맵 조회·첫 방 플레이·최고 기록 저장이 연결되어 있다. 작업 트리에는 로비 사물 애니메이션, 대시보드 기록 조회, 게임 픽셀 UI, 힌트 설정 스키마 변경이 추가되어 있다. 미완료 범위는 [DB·게임 연동](DB_게임_연동.md)과 [대시보드](A_임시_대시보드.md)를 따른다.

## 작성 및 연결 원칙

- 현재 구현의 생성자·메서드·DTO를 기준으로 변경한다. 주석은 책임·제약·스레드 경계를 설명하고 구현 예정 계약을 중복하지 않는다.
- `Main`은 JDBC 저장소와 서비스를, `AppScreens`는 화면과 게임 어댑터·위젯을 조립한다.
- `GamePage`는 `GamePort`와 `Widgets`를 받는다. 개별 위젯이나 `GameFacade`를 직접 생성하지 않는다.
- Swing 변경과 게임 상태 전이는 EDT에서, DB 조회·저장과 비밀번호 검증은 작업 스레드에서 수행한다.
- 서비스는 저장소 인터페이스에 의존한다. 현재 `DashboardRecords`는 예외적으로 `Database`를 직접 받아 읽기 전용 SQL을 실행한다.
- `shared/ui`는 글꼴·색·배치·이미지·전환을 제공한다. `ItemSprite`는 현재 `ItemId`를 참조하므로 엄격한 단방향 FSD를 완전히 충족하지는 않는다.
- 관련 단일 행 선언·대입은 `=`를 세로 정렬한다. Checkstyle 검사와 언어 문법을 우선하며 무관한 코드는 재정렬하지 않는다.

## 추가 UI 구성요소

| 파일 | 연결 범위 | 역할 |
| --- | --- | --- |
| `app/DashboardCat.java`, `DashboardBell.java`, `CatReactionFrames.java`, `WindowAmbient.java` | A 화면 | 고양이·벨·창문 애니메이션과 프레임 수명 |
| `pages/mapselect/MapSelectionPreview.java` | C 화면 | 맵 선택 화면을 확인하는 독립 미리보기 진입점 |
| `app/SceneObjectButton.java` | A 화면 | 로비 사물의 프레임·윤곽선·입력과 타이머 수명 |
| `app/DashboardRecordDialog.java` | A 화면 | 비동기 기록 조회, 방 선택, 새로고침과 취소 |
| `features/dashboard/DashboardRecords.java` | A 화면 ↔ G DB | 방 목록·순위·진척도 읽기 전용 JDBC 조회 |
| `shared/ui/GameOverlayLayout.java` | A 조립 ↔ F 위젯 | 방 위에 헤더·단서·입력·인벤토리·결과 배치 |
| `shared/ui/ItemSprite.java` | F UI | 메모·열쇠 픽셀 아이콘 |
| `shared/ui/PixelTheme.java` | F UI | 공통 글꼴·색·물체 에셋·버튼 렌더링 |

위 표의 연결 범위는 현재 사용 관계이며 기존 7인 담당 배정을 변경하지 않는다. 새 공통 파일의 최종 소유권은 팀 역할 분담 시 확정한다.
