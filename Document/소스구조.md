# Java 소스 구조 및 초안 작성 원칙

이 구조는 클래스 설계안의 구현 시작점이다. 현재 앱 기능은 구현되어 있지 않다.

## 작성 원칙

- 실제 코드는 package, 필요한 import, public class/interface/enum 선언, extends/implements 관계까지만 작성한다.
- 필드·생성자·메서드·enum 상수·SQL은 주석으로 예정 작업을 설명한다. 가짜 반환값이나 미완성 메서드 본문을 만들지 않는다.
- 각 파일의 주석에 담당자, 역할, 연결할 패키지, 구현할 동작과 경계 조건을 적는다.
- 일반 클래스는 명시적 상속 없이 사용한다. 화면은 javax.swing.JFrame 또는 javax.swing.JPanel, 저장 예외는 java.lang.RuntimeException을 상속한다.
- Jdbc 저장소는 같은 엔티티 패키지의 Repository 인터페이스를 구현한다. 인터페이스는 아직 비어 있으므로 구현 단계에서 메서드 선언과 @Override 구현을 함께 추가한다.
- 결과 DTO는 찾기 쉽게 별도 파일로 두었다. 구현 시 팀의 JDK 버전에 맞춰 불변 클래스 또는 record로 작성한다.
- 상속과 객체 참조는 다르다. 예를 들어 GamePage는 GameFacade를 상속하지 않고 생성자로 전달받아 사용한다. 예정 참조는 주석에 적혀 있다.
- app → pages → widgets → features → entities → shared 방향으로 참조한다. 중간 계층은 건너뛸 수 있지만 같은 계층의 다른 슬라이스를 직접 참조하지 않는다.
- 구체 JDBC 객체는 app.Main에서 조립하고, Swing 화면 생성·변경은 EDT에서, DB와 비밀번호 검증은 작업 스레드에서 수행한다.
- Factory, 별도 이벤트 버스, 상태별 클래스를 추가하지 않는다. 빌드 도구·JDBC 드라이버 추가는 실제 구현 단계에 진행한다.
