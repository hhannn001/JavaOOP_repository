# CODE ROOM TodoPlan

이주한의 2026-11-19 제안과 후속 요청을 기준으로, 독립 맵마다 최대 5문제를 구성할 수 있도록 개선한다. 한 맵의 단서, 퍼즐 풀이, 방의 상태, 타이머는 그 맵의 플레이 세션에 속한다. HUD의 전체 문제 수는 현재 맵에 등록된 수를 표시한다.

레이튼에서 참고할 흐름은 **방을 조사해 단서를 얻고, 퍼즐을 풀어 눈앞의 사물을 바꾸는 것**이다. 책상 위 접힌 메모를 습득하면 단서 수첩에서 읽을 수 있고, 서랍 문제를 풀면 닫힌 서랍 이미지가 열린 서랍 이미지로 바뀐다. 퍼즐 창을 닫고 돌아와도 그 플레이에서는 서랍이 열린 채로 보인다. [Nintendo 공식 게임 소개](https://www.nintendo.com/en-gb/Games/Nintendo-DS/Professor-Layton-and-the-Curious-Village-272563.html)

## 구현 순서

한 단계씩 구현하고 확인한 뒤 다음 번호로 넘어간다. 담당은 [기존 역할표](클래스설계_및_7인_역할분담.md)를 기준으로 잡았다.

| 순서 | 담당 | 작업 및 완료 기준 |
| --- | --- | --- |
| 1. 발표용 코드 가독성 | F | 코드 영역만 따뜻한 암갈색 배경과 밝은 18pt 고정폭으로 조정한다. 종이 에셋과 방 화면의 구도를 유지한다. 긴 줄은 화면 폭에 맞춰 시각적으로 줄바꿈하고, 원본 들여쓰기는 유지한다. 발표 환경에서 뒷자리에서 읽어 본다. 코드 표시 변경을 적용했다. 발표 환경 확인은 남아 있다. |
| 2. 맵별 최대 5문제 지원 | E·G | `GameFacade`의 2문제 고정 검사와 `GameSession`의 서랍·금고 중심 상태를 맵별 구성으로 바꾼다. 문제 ID, 활성 조건, 입력 유형, 풀이 결과를 연결한다. 기존 서재 2문제와 5문제 맵 모두 끝까지 풀 수 있고, 중복 제출이나 맵 재입장이 다른 세션에 영향을 주지 않는다. 기존 DB의 계정과 기록을 보존한다. |
| 3. 개별 사물 에셋과 상태 전환 | D·E·A | 방 배경에서 책상 위 메모, 서랍, 밸브, 레버, 문처럼 상태가 바뀌거나 조사할 물체를 투명 에셋으로 분리한다. 서재 서랍의 닫힘·열림부터 실제 풀이 상태와 연결한다. 정답 직후 열리는 효과를 보여주고, 이후 열린 이미지와 클릭 영역이 유지된다. 재도전은 닫힌 상태에서 시작한다. |
| 4. 조사와 습득으로 힌트 획득 | F·D·E | 예를 들어 책상 위 접힌 메모를 조사해 주우면 방에서 메모가 사라지고 수첩에 등록된다. 관련 퍼즐은 획득한 힌트만 다시 보여준다. 오답·창 닫기·중복 조사 후에도 등록과 상태가 일치한다. |
| 5. 드래그 퍼즐 | F·E·D | 첨부 이미지의 블록 조작처럼 사물이 포인터를 따라 움직인다. 허용 위치에 놓으면 배치가 확정되고, 이미 채워진 자리에 놓으면 두 사물의 위치를 바꾸고, 범위 밖의 드롭은 원래 위치로 돌아간다. 재시작과 재시도를 제공한다. 서랍과 같은 진행 보상은 확정된 정답에만 연결한다. |
| 6. 기계실과 기록보관소 | C·D·E·F·G | 아래 기계실 5문제를 세션에 연결하고 기록보관소에는 별도 단서와 퍼즐을 배치한다. 기록보관소 구성은 방의 이야기와 함께 확정한다. 각 맵은 독립적으로 입장부터 탈출까지 확인한 뒤 선택 화면에서 활성화한다. |
| 7. 진행 HUD와 기록 | A·G | 풀이 수/이 맵 전체 문제, 경과 시간, 현재 계정의 해당 맵 최고 기록을 표시한다. 첫 도전, 정답 직후, 탈출 후, 재도전에서 값이 일치한다. 기존 맵의 시간·퍼즐 규칙이 바뀌면 이전 기록과의 비교 기준을 확정한다. |
| 8. 커서와 상호작용 피드백 | D·A·F | 기본·조사·드래그 상태에 맞춰 커서를 바꾸고, 키보드 포커스에도 단서를 준다. 창 크기를 바꿔도 이미지와 클릭 영역이 맞고 애니메이션이 입력을 가로막지 않는다. |

| 10. 통합 QA와 발표 리허설 | 전원 | 세 방에서 초회·재도전, 힌트 습득, 오답·드롭 실패, 방 상태 초기화, 계정별 기록을 확인한다. 발표 화면에서 코드와 HUD를 뒷자리에서 읽고 첫 조사 지점을 사전 설명 없이 찾을 수 있는지 관찰한다. |

## 구현 상태

서재 2문제, 기록보관소 3문제, 기계실 5문제를 각각 플레이할 수 있다. 기록보관소와 기계실의 인게임 배경은 큰 형태와 빈 공간을 살리고, 조작 장치는 배경과 분리했다. 현재 풀 수 있는 장치를 누르면 다가가며, 문제를 닫거나 해결하면 원래 시점으로 부드럽게 돌아간다. 대사창은 인벤토리를 가린다. 장치가 풀리면 열린 그림이나 활성 표시로 짧게 전환한 뒤 새 상태를 유지한다.

현재 구현과 별도로 기계실과 온실의 다음 버전을 설계했다. 각 맵은 코딩 3문제와 조작 게임 2문제로 구성한다. 공간 배치, 방마다 세 곳의 코딩 기록과 설비에 붙은 행동 표시, 병행 가능한 풀이 흐름은 각 설계서에서 관리한다.

### 장면을 먼저 완성한 뒤 에셋 분리

두 방의 완성 구도를 먼저 만들고, 같은 구도에서 물체가 빠진 배경판과 투명 레이어를 제작한다. 원래 위치에 합성했을 때 완성 장면과 일치하는지 확인한 다음 클릭 영역과 애니메이션을 연결한다. 방 화면 아래에 인벤토리 공간을 예약하고, 공간 위쪽에 방 전체를 맞춰 온실 운반차와 기계실 압력 피트가 인벤토리에 덮이지 않게 한다. [장면 분리와 배치 좌표](design/room-redesign/README.md)

### 시간과 환경 상태의 공통 규칙

기계실과 온실은 각각의 설비와 환경 변화를 통해 제한시간을 알린다. 초안은 시작·25%·50%·75%·만료 다섯 구간이며 180초 기준 0·45·90·135·180초다. 실제 제한시간을 조정해도 같은 비율을 적용한다. 시간과 퍼즐 조건은 세션을 기준으로 계산하고, 방 전체와 근접 뷰가 같은 상태를 그린다. 잠깐 닫았던 방 화면에서 예전 단계의 효과를 다시 재생할 필요는 없다.

시간 연출은 필수 증거를 없애거나 관찰 순서를 고정하지 않는다. 완료한 조작은 유지하며, 만료는 한 번만 처리한다. 재도전에서는 환경과 퍼즐을 함께 초기화한다. 25%·50%·75%에 GUI를 가린 상태에서도 플레이어가 달라진 물체 하나를 알아볼 수 있는지 확인한다. 정답과 만료가 같은 프레임에 들어오면 제한시간 전에 확정된 탈출만 성공으로 처리한다.

## 일정과 검증

회의록 기준으로 4주차 월요일 기능 통합을 목표로 하고, 이후 1주간 교차 QA를 거쳐 5주차에 발표한다. 기능 확인에는 JDK 17에서 `./mvnw clean verify`와 실제 Swing 창을 사용한다. 플레이어가 멈춘 지점, 입력 순서, 재현 결과는 [QA 체크리스트](QA_체크리스트.md)에 기록한다.

2026-11-23 macOS 데스크톱 세션에서 실제 Swing 창과 숫자 키 입력을 포함한 전체 테스트 85개가 통과했다. 드래그의 범위 밖 드롭·자리 교체·초기화, 잠긴 장치의 확대 생략, 문제 닫기 후 카메라 복귀를 회귀 테스트에 추가했다. 현장 발표 리허설과 뒷자리 가독성 확인은 남아 있다.
